The Green Algeria
Design System

An implementation of Green Algeria's design language. Night-soil canvas — living canopy green as the one accent in both themes. Terracotta clay as secondary, wildfire amber reserved for fire reports, wadi blue for the care system. Built for a crowdsourced movement, not a storefront — trust and clarity over spectacle.

Behavior

UX Principles

Tokens control how Green Algeria looks. This section controls how it behaves — the cognitive/interaction rules that stop AI-generated screens from reading as generic. Feed these verbatim into any build prompt alongside the tokens above.

Perception & Visual Hierarchy
Jakob's Law
Users expect your product to work like every other product they already know.
Rule: don't invent novel patterns for cart, nav, or settings icons. Match convention; save originality for brand moments, not navigation.
Law of Proximity
Items placed close together are perceived as related.
Rule: group related fields/actions with tight spacing (--s-xs/--s-sm), separate unrelated groups with --s-lg or more. Spacing IS the hierarchy.
Law of Similarity
Elements that look alike are read as belonging to the same category.
Rule: one visual style per action-type across the whole app (all destructive actions look alike, all primary CTAs look alike). Never reuse a style for two different meanings.
Law of Prägnanz
People simplify complex shapes into the simplest form they can.
Rule: default to the simplest layout that communicates the hierarchy. If a screen needs a legend to explain itself, simplify it instead.
Von Restorff Effect
The one item that looks different is the one people remember and click.
Rule: exactly one visually distinct element per screen — the primary CTA. If everything is emphasized, nothing is.
Uniform Connectedness
Elements visually connected (shared border, background, or line) read as one unit.
Rule: wrap related inputs/actions in a shared card-demo container rather than relying on spacing alone when the relationship needs to be unmistakable.
Interaction & Motor Effort
Fitts's Law
Time to reach a target depends on its size and distance from the cursor/thumb.
Rule: primary actions get the largest tap target and sit within thumb reach on mobile (bottom third). Never shrink a frequent action to fit visual balance.
Hick's Law
More choices = longer decision time, non-linearly.
Rule: cap visible primary choices at 5-7. Beyond that, group into categories or progressively disclose — don't just list everything flat.
Doherty Threshold
Interfaces feel "instant" below ~400ms response; above it, users disengage.
Rule: any action over 400ms gets immediate optimistic UI or a skeleton/spinner using --dur-fast, not a frozen screen.
Tesler's Law
Every process has inherent complexity that can't be removed, only relocated.
Rule: when a flow feels complex, the question is who absorbs it — the system (better defaults, smart validation) or the user (more fields). Default to absorbing it yourself.
Postel's Law
Be liberal in what you accept from users, strict in what you output.
Rule: forms should accept loose input (phone formats, spacing, casing) and normalize it silently, not reject and blame the user.
Memory & Information Load
Miller's Law
Working memory holds about 7 (±2) items at once.
Rule: chunk long lists/nav into groups of 5-7 with labels (exactly what this file's sidebar already does with nav-group).
Serial Position Effect
Users remember the first and last items in a list best; the middle gets lost.
Rule: put the most important nav item or CTA first or last, never buried mid-list.
Peak-End Rule
People judge an experience mainly by its most intense moment and how it ends.
Rule: invest polish in the single most emotional moment of a flow (checkout success, order placed) and the final screen — not equally everywhere.
Zeigarnik Effect
Unfinished tasks stay top-of-mind more than completed ones.
Rule: show progress indicators (step 2 of 4, % complete) on multi-step flows — the visible incompleteness is what drives completion.
Trust, Errors & Constraints
Parkinson's Law
A task expands to fill the time/space allotted to it.
Rule: constrain input fields to the length you actually need (short bio field stays short) — generous space invites bloated, unusable content.
Occam's Razor
The simplest solution that solves the problem is usually the right one.
Rule: before adding a setting, modal, or extra step, ask if removing something gets the same result. Default to fewer screens.
Pareto Principle
Roughly 80% of usage comes from 20% of features.
Rule: that 20% gets the polish, the fast path, and the largest tap targets. Everything else can be one tap deeper.
Error Prevention
A well-designed system stops mistakes before they happen rather than explaining them after.
Rule: disable submit until required fields are valid, confirm destructive actions, use --error color the instant a field goes invalid — not only on submit.
Visibility of System Status
Users need to always know what's happening — loading, saved, failed, empty.
Rule: every async action gets a state for loading, success (use .toast), error, and empty. Never leave a screen ambiguous about what just happened.
WCAG Contrast
Text needs sufficient contrast against its background to be legible for all users.
Rule: body text ≥4.5:1 contrast, large text ≥3:1. --on-surface-muted is already tuned for this in both themes — don't introduce new lighter grays.
