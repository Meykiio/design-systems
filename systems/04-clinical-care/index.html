Clinical Care
Design System

Medical cyan & coral palette, measured motion, generous reading density. Design thesis: clarity is care — information hierarchy that stays readable at 3am under stress.

Reference 04 · Accessibility

Accessibility Leads

In clinical software accessibility is not a feature, it is the product. Everything here starts from the constraint set.

Focus Rings3px primary glow on every interactive element. Never removed, never dimmed.
Color IndependenceEvery state pairs color with icon or label. Critical info never relies on hue alone.
Contrast Floors4.5:1 normal text, 3:1 large text — verified on both themes and all status tints.
Touch Sizes44x44 minimum. Stressed users mis-tap; generous targets are a safety feature.
Reduced MotionAll transitions become instant when prefers-reduced-motion is set.
Reading LoadBody text 15px/1.6 minimum. Medical copy never uses small or dim text.

One self-contained HTML file per system. Zero build step.
Reference 04 · Security

Patient Data Security

HIPAA-grade patterns: minimal exposure, full audit, strict access.

RLS on Every Table
Row-level security scoped per patient and per care team membership.
Access Audit
Every record view logs who, when, and why. Patients can export their log.
Encrypted at Rest
AES-256 at rest, TLS 1.3 in transit. Backups encrypted with separate keys.
Break-Glass Protocol
Emergency access is allowed, loudly logged, and reviewed within 24 hours.

Reference 04 · Architecture

Architecture

Clinical stack: record-anchored views, autosave, audit chain.

Record Anchor
One patient record object drives all views; vitals, meds, labs read from it.
Autosave Pipeline
Debounced 2s persistence with server acknowledgment and offline queue.
Alert Routing
Critical alerts fan out to assigned staff within seconds, with ack tracking.
Audit Chain
Hash-linked, append-only audit log covering every record touch.
