Your receipts,

Receipto turns paper and photo receipts into searchable expenses, live inventory, and honest insights. Free, private, open source, and runs on your machine. No AI required to work. Built for Algerians first, open to the world.

Data & Security

Trust nothing the client sends. These rules are the difference between a demo and something safe to put real users' financial data into.

Trust Boundary
Input & Output
Pre-Ship Security Checklist
AreaCheckWhy it matters
AuthEvery protected route/endpoint checks identity server-sideA hidden UI element is not access control
AuthorizationOwnership/role checked per-row, not just per-endpointPrevents one user reading/editing another's receipts
StorageReceipt images in a private bucket with per-user policiesPublic URLs leak financial documents to anyone with the link
SecretsNo API keys, service roles, or tokens in client bundle or git historyLeaked keys grant full account access
InputAll user input validated and length-limited server-sideBlocks injection and malformed-data corruption
TransportHTTPS enforced, no mixed contentPrevents interception of tokens/data in transit
Rate limitingAuth, write, and expensive endpoints (AI parsing) are rate-limitedStops brute-force and cost-abuse from one bad actor
ErrorsError responses never leak stack traces or internal detail to the clientPrevents handing attackers a map of the system
Engineering

Performance & Scale

Most performance problems are architectural, not algorithmic. These are the decisions that determine whether Receipto still feels fast at 100x the data — made once, early, rather than patched under pressure later.

Data Access Shape
System Shape
Complexity Sanity Check
PatternCost as data growsUse when
Indexed lookupO(log n) — stays fastAny query on a column filtered/sorted often
Paginated listO(page size) — constantAny endpoint returning a collection (receipts, movements)
Full table scanO(n) — degrades linearlyAcceptable only on small, bounded tables (e.g. a config table)
Nested loop query (N+1)O(n·m) — degrades fastNever intentionally — always the sign to batch/join
Engineering

AI & Privacy

Receipto's core works with zero AI. AI is an opt-in, provider-agnostic layer the user switches on, and it must never be required, never default-on, and never ambiguous about where data goes.

Product Rules (binding)
AI Opt-in Card Pattern
AI parsing is off

Your receipts are read locally: PDF text layers and open-source OCR. Turn AI on to get higher-accuracy parsing, a chat assistant, and AI reports. Only then is any data sent to the provider you choose.

Your keys stay yours

Use Gemini with a server-side key, or bring your own key to OpenAI, Groq, OpenRouter, or a fully local model via Ollama. Local models work offline and nothing leaves your machine.

Localization

RTL & Arabic

Arabic is the first-class audience. The layout must mirror, not just translate: build with CSS logical properties so every screen flips correctly, and ship a real Arabic webfont (Cairo) instead of relying on system rendering.

Binding Rules
RuleImplementationWhy
Logical propertiespadding-inline-start, margin-inline-end, text-align:start, inset-inlineOne codebase mirrors for RTL with no duplicate layouts
Font--font-arabic: 'Cairo', system-ui, sans-serif loaded as a webfontSystem Arabic rendering is inconsistent; Cairo is a designed Arabic+Latin family
DigitsLocale-driven digit set (Latin or Arabic-Indic) and DZD groupingNumbers must render in the user's expected format
IconsDirection-aware icons (arrows, chevrons, back buttons mirror)An un-mirrored arrow breaks mental flow in RTL
Never hardcodeAll strings via i18next; components render from the active localeArabic is a locale, not a translation pass bolted on
  • Set dir="rtl" on the document root for Arabic — not on individual containers
  • Check every new screen in RTL, dark mode, and mobile before merging (AGENTS.md rule 9)
  • The camera/primary CTA must stay thumb-reachable regardless of direction
